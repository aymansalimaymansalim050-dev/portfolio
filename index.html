About

A little about how I work

I'm a front-end developer who cares as much about how an interface feels to use as how the code behind it reads a year from now. I like small, well-tested components over clever one-off solutions, and I write things down so the next person — often future me — doesn't have to guess.

Outside of shipping features, I'm usually learning something adjacent: accessibility patterns, a new CSS layout technique, or just reading through a library's source to understand a decision it made.
